# LLM Scraper — APIs and Interfaces

## Public API Overview

The entire public surface is one class: `LLMScraper` (default export from `llm-scraper`). It exposes three async methods: `run()`, `stream()`, and `generate()`. All methods accept a Playwright `Page` as their first argument, making the library a post-navigation extraction layer that sits on top of an existing Playwright browser session.

### Constructor


Accepts any Vercel AI SDK `LanguageModel` instance. The model is stored and reused for all calls on this scraper instance.

```ts
import { openai } from '@ai-sdk/openai'
import LLMScraper from 'llm-scraper'

const scraper = new LLMScraper(openai('gpt-4o'))
```

Compatible model providers (any package producing a `LanguageModel`):
- `@ai-sdk/openai` — `openai('gpt-4o')`, `openai('gpt-4o-mini')`, etc.
- `@ai-sdk/anthropic` — `anthropic('claude-3-5-sonnet-20240620')`
- `@ai-sdk/google` — `google('gemini-1.5-flash')`
- `ollama-ai-provider-v2` — `ollama('llama3')`, `ollama('gemma3:1b')`
- `@ai-sdk/openai` with custom `baseURL` — Groq, Together, any OpenAI-compatible API

### `scraper.run(page, output, options?)`

**File**: `src/index.ts:29`

Extracts structured data from the page and returns it as a typed object.

```ts
async run<OUTPUT extends Output.Output>(
  page: Page,
  output: OUTPUT,
  options?: ScraperRunOptions
): Promise<{ data: InferOutput<OUTPUT>, url: string }>
```

**Parameters**:
- `page` — Playwright `Page` that has already navigated to the target URL
- `output` — Vercel AI SDK `Output` descriptor (see Output Types below)
- `options` — optional, see `ScraperRunOptions` below

**Returns**: `{ data, url }` where `data` is typed per the schema.

**Example** (Zod schema, html format):
```ts
import { chromium } from 'playwright'
import { z } from 'zod'
import { Output } from 'ai'
import { openai } from '@ai-sdk/openai'
import LLMScraper from 'llm-scraper'

const browser = await chromium.launch()
const page = await browser.newPage()
await page.goto('https://news.ycombinator.com')

const scraper = new LLMScraper(openai('gpt-4o'))

const schema = z.object({
  top: z.array(z.object({
    title: z.string(),
    points: z.number(),
    by: z.string(),
    commentsURL: z.string(),
  })).length(5).describe('Top 5 stories on Hacker News'),
})

const { data } = await scraper.run(page, Output.object({ schema }), {
  format: 'html',
})

console.log(data.top) // typed as { title: string, points: number, ... }[]
```

### `scraper.stream(page, output, options?)`

**File**: `src/index.ts:38`

Streams partial objects as they are generated by the LLM.

```ts
async stream<OUTPUT extends Output.Output>(
  page: Page,
  output: OUTPUT,
  options?: ScraperRunOptions
): Promise<{ stream: AsyncIterable<DeepPartial<InferOutput<OUTPUT>>>, url: string }>
```

**Returns**: `{ stream, url }` where `stream` is `partialOutputStream` from Vercel AI SDK's `streamText`.

**Example** (streaming single object):
```ts
const { stream } = await scraper.stream(page, Output.object({ schema }), {
  format: 'html',
})

for await (const partial of stream) {
  console.log(partial) // receives partial objects as tokens arrive
}
```

**Example** (streaming array):
```ts
const { stream } = await scraper.stream(
  page,
  Output.array({ element: storySchema }),
  { format: 'raw_html' }
)

let items = []
for await (const partial of stream) {
  items = partial
}
```

### `scraper.generate(page, output, options?)`

**File**: `src/index.ts:48`

Asks the LLM to generate a reusable JavaScript scraping function instead of extracting data directly.

```ts
async generate<OUTPUT extends Output.Output>(
  page: Page,
  output: OUTPUT,
  options?: ScraperGenerateOptions
): Promise<{ code: string, url: string }>
```

**Returns**: `{ code, url }` where `code` is a JavaScript IIFE string that can be passed to `page.evaluate()`.

The generated code is intended to be executed with `page.evaluate()` on subsequent visits to extract the same schema without LLM calls.

**Example**:
```ts
const { code } = await scraper.generate(page, Output.object({ schema }), {
  format: 'raw_html',
})

// Execute the generated code on the same (or future) page
const result = await page.evaluate(code)
const data = schema.parse(result) // validate with Zod
console.log(data)
```

The LLM is instructed to generate an IIFE with no imports, no comments, and no `console.log` — pure executable JavaScript returning data conforming to the schema.

- `messages` — additional messages appended after the page content message

### `ScraperGenerateOptions`

**File**: `src/index.ts:18`

```ts

  format?: 'html' | 'raw_html'

```

Like `ScraperLLMOptions` but `format` is restricted to `html` or `raw_html` (code generation only supports text-based formats, not image/markdown/text/custom).

## Output Types (Vercel AI SDK)

The `output` parameter to all three methods uses Vercel AI SDK's `Output` namespace:

### `Output.object({ schema })`

Extract a single structured object. Schema can be Zod or JSON Schema:

```ts
import { Output } from 'ai'
import { z } from 'zod'

// Zod schema
Output.object({ schema: z.object({ title: z.string() }) })

// JSON Schema
import { jsonSchema } from 'ai'
Output.object({ schema: jsonSchema({ type: 'object', properties: { title: { type: 'string' } } }) })
```

### `Output.array({ element })`

Extract an array of items matching the element schema:

```ts
Output.array({ element: z.object({ title: z.string(), points: z.number() }) })
```

## Format Modes Reference

Passed as `options.format` to `run()`, `stream()`, or `generate()`:

| Format | Description | Token cost | Best for |
|--------|-------------|------------|---------|
| `html` | Cleaned HTML (default) — scripts, forms, images removed | Medium | Most extraction tasks |
| `raw_html` | Full unprocessed HTML | High | When context is needed |
| `markdown` | Turndown Markdown conversion | Low-Medium | Article/content pages |
| `text` | Mozilla Readability text extraction | Low | Long article text |
| `image` | Base64 screenshot | High | Multimodal models, visual layout |
| `custom` | Caller-provided function | Varies | Special preprocessing needs |

## Integration Patterns

### Pattern 1: Basic One-Shot Extraction

```ts
const browser = await chromium.launch()
const page = await browser.newPage()
await page.goto('https://example.com/products')

const scraper = new LLMScraper(openai('gpt-4o'))
const { data } = await scraper.run(page, Output.object({ schema: productSchema }))

await page.close()
await browser.close()
```

### Pattern 2: Custom System Prompt

Override the default system prompt to give the LLM more specific instructions:

```ts
const { data } = await scraper.run(page, Output.object({ schema }), {
  format: 'html',
  system: 'You are a price comparison engine. Extract only pricing data.',
})
```

### Pattern 3: LLMScraper as an AI Agent Tool

Compose the scraper inside a Vercel AI SDK `tool()` for use in agentic workflows:

```ts
import { generateText, tool, Output, stepCountIs } from 'ai'
import { z } from 'zod'

const { text } = await generateText({
  model: openai('gpt-4o-mini'),
  tools: {
    scrapeWebsite: tool({
      description: 'Scrape a website with a given schema and URL',
      inputSchema: z.object({ url: z.string(), jsonSchema: z.string() }),
      execute: async ({ url, jsonSchema }) => {
        const browser = await chromium.launch()
        const page = await browser.newPage()
        await page.goto(url)
        const schema = toJSONSchema(JSON.parse(jsonSchema))
        const result = await scraper.run(page, Output.object({ schema }))
        await browser.close()
        return result.data
      },
    }),
  },
  stopWhen: stepCountIs(2),
  prompt: 'List top stories from HackerNews and summarize them',
})
```

### Pattern 4: Code Generation for Repeated Scraping

Generate a scraping function once, then reuse it without LLM calls:

```ts
// Generate once
const { code } = await scraper.generate(page, Output.object({ schema }))
// Save `code` to disk or a database

// Execute on subsequent page loads (no LLM call)
const result = await page.evaluate(savedCode)
const data = schema.parse(result)
```

### Pattern 5: Local Model with Ollama

```ts
import { ollama } from 'ollama-ai-provider-v2'

const scraper = new LLMScraper(ollama('llama3'))
const { data } = await scraper.run(page, Output.object({ schema }), {
  format: 'html', // image format not supported for text-only models
})
```

### Pattern 6: Custom Preprocessing

Supply any preprocessing logic as a function:

```ts
const { data } = await scraper.run(page, Output.object({ schema }), {
  format: 'custom',
  formatFunction: async (page) => {
    // Extract only the main article content
    return page.innerText('article.main-content')
  },
})
```

## Configuration and Extension Points

### Overriding System Prompts

Both `run()`/`stream()` and `generate()` accept a `system` field that replaces the built-in prompts:
- Default for run/stream: `"You are a sophisticated web scraper. Extract the contents of the webpage"`
- Default for generate: instructs LLM to write an IIFE JavaScript function

### Additional Messages

Inject extra messages (e.g., few-shot examples, previous conversation turns) via `options.messages`:

```ts
const { data } = await scraper.run(page, Output.object({ schema }), {
  messages: [
    { role: 'assistant', content: 'I will extract exactly 5 items.' },
  ],
})
```

### AI SDK CallSettings passthrough

All Vercel AI SDK `CallSettings` are accepted and forwarded to `generateText`/`streamText`:
- `temperature`
- `maxTokens`
- `topP`
- `frequencyPenalty`
- `presencePenalty`
- `seed`
- `headers` (for custom API headers)
- etc.

### `fullPage` Screenshot

For `image` format, control whether a full-page screenshot is captured:

```ts
const { data } = await scraper.run(page, Output.object({ schema }), {
  format: 'image',
  fullPage: true,
})
```
