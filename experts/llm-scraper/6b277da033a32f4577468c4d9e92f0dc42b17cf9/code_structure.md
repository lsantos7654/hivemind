## Module and Package Organization

The library follows a minimal flat-module layout inside `src/`. There are no subdirectories — all four source files reside at the top level, each with a single clear responsibility. The compiled output in `dist/` mirrors this structure exactly.

The package uses ES modules (`"type": "module"` in `package.json`) with `NodeNext` module resolution and `NodeNext` module format in TypeScript. All internal imports use explicit `.js` extensions to comply with ESM Node.js requirements.

### Export surface

The package's main entry is `dist/index.js`. The public API exported from `src/index.ts` is:

- `LLMScraper` (default export) — the primary class
- `ScraperLLMOptions` (named type export) — options for `run()` and `stream()`
- `ScraperGenerateOptions` (named type export) — options for `generate()`

The `preprocess.ts` exports (`PreProcessOptions`, `PreProcessResult`, `preprocess`) are used internally but not re-exported from the index, making them implementation details.

## Main Source Files and Their Roles

### `src/index.ts` — Public API and `LLMScraper` class

The sole entry point consumers interact with. Defines the `LLMScraper` class and the option types that appear in the public API.

- **Constructor**: Accepts a Vercel AI SDK `LanguageModel` instance (e.g., `openai('gpt-4o')`), stored as `this.client`.
- **`run(page, output, options?)`**: Synchronously preprocesses the page then calls `generateAISDKCompletions`. Returns `{ data, url }` where `data` is typed to match the output schema.
- **`stream(page, output, options?)`**: Preprocesses then calls `streamAISDKCompletions`. Returns `{ stream, url }` where `stream` is an async iterator of partial objects.
- **`generate(page, output, options?)`**: Preprocesses then calls `generateAISDKCode`. Returns `{ code, url }` where `code` is a runnable JavaScript IIFE string.

Type parameters:
- `OUTPUT extends Output.Output` — generic that carries schema type information through to the return type
- `ScraperRunOptions` is a private intersection of `ScraperLLMOptions & PreProcessOptions`

### `src/preprocess.ts` — Page Content Extraction

Handles all page-to-string (or page-to-base64) conversion before LLM submission.

**Exported types**:
- `PreProcessOptions` — discriminated union covering each format variant. For `image`, adds optional `fullPage`. For `custom`, adds required `formatFunction`.
- `PreProcessResult` — `{ url: string, content: string, format: PreProcessOptions['format'] }`

**`preprocess(page, options)` function logic** (by format):

| Format | Mechanism |
|--------|-----------|
| `html` | Injects and runs `cleanup()` in browser context, then calls `page.content()` |
| `raw_html` | Direct `page.content()` — no processing |
| `markdown` | `page.innerHTML('body')` → Turndown conversion |
| `text` | `page.evaluate()` loads Mozilla Readability from CDN, returns title + textContent |
| `image` | `page.screenshot()` → base64 string |
| `custom` | Calls the caller-provided `formatFunction(page)` |

Default format when none is specified: `'html'`.

### `src/cleanup.ts` — DOM Cleanup

A single default-exported function designed to be passed to `page.evaluate()`. Runs entirely in the browser context (not in Node.js). Removes elements that add noise without semantic value and strips non-content attributes.

**Elements removed**: `script`, `style`, `noscript`, `iframe`, `svg`, `img`, `audio`, `video`, `canvas`, `map`, `source`, `dialog`, `menu`, `menuitem`, `track`, `object`, `embed`, `form`, `input`, `button`, `select`, `textarea`, `label`, `option`, `optgroup`, `aside`, `footer`, `header`, `nav`, `head`.

**Attribute prefixes stripped**: `style`, `src`, `alt`, `title`, `role`, `aria-`, `tabindex`, `on` (event handlers), `data-`.

This cleanup dramatically reduces HTML token count before sending to the LLM, reducing costs and improving extraction accuracy.

### `src/models.ts` — AI SDK Integration

Contains three exported async functions that wrap Vercel AI SDK calls.

**`generateAISDKCompletions(model, page, output, options?)`**:
- Builds user content: text array for text-based formats, image array for `image` format
- Merges caller messages with the page content message
- Calls `generateText({ model, output, system, messages, ...rest })`
- Returns `{ data: result.output, url: page.url }`

**`streamAISDKCompletions(model, page, output, options?)`**:
- Same message construction as above
- Calls `streamText(...)` and returns `{ stream: partialOutputStream, url }`
- Does NOT await — returns immediately with the stream

**`generateAISDKCode(model, page, output, options?)`**:
- Extracts JSON Schema from the `output.responseFormat`
- Uses a different system prompt (`systemCodePrompt`) instructing the LLM to write a JavaScript IIFE
- Combines URL, schema, and page content into a single user message
- Calls `generateText(...)` with plain text output (no structured output mode)
- Strips markdown code fences from response via `stripMarkdownBackticks()`
- Returns `{ code: string, url: string }`

**System prompts** (hardcoded strings):
- Default: `"You are a sophisticated web scraper. Extract the contents of the webpage"`
- Code mode: Instructs LLM to write IIFE JavaScript that returns data matching the schema with no comments, imports, or console.log

## Tests Directory

### `tests/index.ts` — Test Fixture Setup

Provides a Vitest `test` fixture that:
- Lazily launches a shared Chromium browser instance (singleton across test file)
- Creates and closes a fresh `Page` per test via `test.extend`
- Creates one `LLMScraper(openai('gpt-4o-mini'))` instance shared across tests
- Closes the browser in `afterAll`

### `tests/scraper.test.ts` — Integration Tests

Eight end-to-end test cases, each hitting a real URL:
1. Basic Hacker News scrape (default `html` format)
2. Image format scrape (screenshot → multimodal)
3. Markdown format scrape
4. Raw HTML format scrape
5. Code generation scrape
6. JSON Schema (non-Zod) scrape
7. Streaming single-object scrape (example.com)
8. Streaming array scrape from Hacker News

## Code Organization Patterns

- **Separation of concerns**: Each file has exactly one responsibility — no file does both HTTP and parsing.
- **No framework abstractions**: No dependency injection container, no decorators, no ORM. Just functions and classes.
- **ESM-first**: All files use `import`/`export`, explicit `.js` extensions, and top-level `await` in examples.
- **Discriminated union options**: `PreProcessOptions` uses TypeScript discriminated unions (on `format`) to enforce that `formatFunction` is only required when `format === 'custom'` and `fullPage` is only present when `format === 'image'`.
- **Generic passthrough**: `Output.Output` generics flow from the public API through models.ts to preserve schema typing at the call site with no runtime overhead.
