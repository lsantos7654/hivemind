## Module and Package Organization

Koa uses a flat module structure — all core logic lives directly in `lib/`. There are no subdirectories within `lib/`; each file is a self-contained module.

### Core Modules (`lib/`)

**`lib/application.js`** — The `Application` class (extends `EventEmitter`). This is the main entry point (`package.json` `"main"`). It owns:
- The `middleware[]` array
- `use(fn)` — registers middleware
- `listen(...args)` — creates an HTTP server and starts it
- `callback()` — returns the `(req, res)` handler; sets up `AsyncLocalStorage` if configured
- `handleRequest(ctx, fnMiddleware)` — runs the composed middleware chain
- `createContext(req, res)` — instantiates and wires together Context, Request, Response
- `onerror(err)` — default app-level error handler (logs to stderr)
- `respond(ctx)` — (private function, not exported) finalizes the HTTP response by examining `ctx.body` type
- Re-exports `HttpError` from `http-errors` for consumer convenience

**`lib/context.js`** — The Context prototype. One instance is created per request via `Object.create(this.context)`. Key responsibilities:
- `throw(...args)` — delegates to `http-errors`
- `assert` — direct reference to `http-assert`
- `onerror(err)` — per-request error handler; emits `app.emit('error', err, this)`; sets error response
- `cookies` — lazy getter backed by the `cookies` package
- Delegates (via `delegates` package) response methods/accessors: `attachment`, `redirect`, `remove`, `vary`, `has`, `set`, `append`, `flushHeaders`, `back`, `status`, `message`, `body`, `length`, `type`, `lastModified`, `etag`, `headerSent`, `writable`
- Delegates request methods/accessors: `acceptsLanguages`, `acceptsEncodings`, `acceptsCharsets`, `accepts`, `get`, `is`, `querystring`, `idempotent`, `socket`, `search`, `method`, `query`, `path`, `url`, `accept`, `origin`, `href`, `subdomains`, `protocol`, `host`, `hostname`, `URL`, `header`, `headers`, `secure`, `stale`, `fresh`, `ips`, `ip`

**`lib/request.js`** — The Request prototype. Wraps `this.req` (Node's `IncomingMessage`). Notable properties:
- URL parsing is done lazily using `parseurl` for cached parsed URLs
- `query` / `querystring` use `lib/search-params.js` (`URLSearchParams`)
- `host` handles HTTP/2 `:authority` pseudo-header and proxy `X-Forwarded-Host`
- `URL` (WHATWG URL object) is lazily memoized in `this.memoizedURL`
- `fresh` checks cache headers using the `fresh` npm package
- `accepts*` use the `accepts` npm package
- `is()` uses `type-is` package

**`lib/response.js`** — The Response prototype. Wraps `this.res` (Node's `ServerResponse`). Notable behavior:
- `body` setter auto-detects type (string, Buffer, Stream, ReadableStream, Blob, Response, or JSON object) and sets `Content-Type` and `Content-Length` accordingly
- When body is set to `null`, sets status 204 (unless status is already an empty-body code or type is `application/json`)
- `redirect()` sanitizes URLs using `new URL()` and encodes with `encodeurl`
- `back()` validates referrer is same-origin before redirecting
- `type` setter uses `mime-types.contentType()` for lookup by extension or MIME type
- `etag` setter auto-wraps value in quotes if not already quoted

**`lib/is-stream.js`** — Duck-type check for Node.js stream objects. Returns `true` for both `instanceof Stream` and stream-like objects with `readable`, `pipe`, `read`, `destroy`, `destroyed`, and `readableObjectMode`.

**`lib/only.js`** — Tiny utility: `only(obj, keys)` returns a new object with only the specified keys (skipping `null`/`undefined` values). Used in `toJSON()` implementations.

**`lib/search-params.js`** — `parse(str)` and `stringify(obj)` wrappers around `URLSearchParams`. Arrays are serialized as repeated keys. Replaces the legacy Node `querystring` module.

## Code Organization Patterns

1. **Prototype objects, not classes** — `request.js`, `response.js`, and `context.js` export plain objects used as prototypes via `Object.create()`. This avoids inheritance chains while allowing per-instance `Object.create()` to cheaply create per-request objects.

2. **Delegation via `delegates` package** — Rather than copying methods, Context uses `delegates` to proxy method calls and property access through to `request` and `response`. This keeps the Context object thin while making shortcuts like `ctx.body` work.

3. **Lazy initialization** — `request.accept`, `request.URL` (memoized), and `context.cookies` are all computed once on first access.

4. **Symbol-keyed private state** — `context.js` uses `const COOKIES = Symbol('context#cookies')` and `request.js` uses `const IP = Symbol('context#ip')` to avoid property name collisions on the shared prototype.

5. **Dual CJS/ESM export** — `package.json` `"exports"` maps `"require"` → `lib/application.js` and `"import"` / `"default"` → `dist/koa.mjs`. The ESM file is generated at build time.
