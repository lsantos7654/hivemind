# Koa — Repository Summary

## Purpose and Goals

Koa is an expressive, minimal HTTP middleware framework for Node.js, created by the team behind Express. Its core goal is to provide a higher-level abstraction over Node's built-in `http` module while remaining extremely small (~570 SLOC of library code) and shipping with **no bundled middleware**. Koa's design philosophy is to give developers a clean, composable building block for web applications and APIs rather than a batteries-included framework.

The current release is **Koa v3.2.0**, which requires Node.js ≥ 18.0.0. v3 is a significant evolution over v2: it removes support for legacy generator-function middleware, adds `AsyncLocalStorage` integration, adopts the Web WHATWG standards (Blob, ReadableStream, Response), and replaces Node's `querystring` module with `URLSearchParams`.

## Key Features and Capabilities

- **Onion middleware model** — middleware functions are composed into a stack using `koa-compose`. Each middleware can perform work before *and* after calling `await next()`, creating a bidirectional "onion" flow.
- **Async/await native** — the entire middleware signature is `async (ctx, next) => {}`. No callbacks, no generator functions.
- **Context object** — every request creates a single `Context` (ctx) that merges request and response concerns and exposes delegate shortcuts (e.g., `ctx.body`, `ctx.status`, `ctx.method`).
- **Request abstraction** — `ctx.request` wraps Node's `IncomingMessage` with helpers for content negotiation, query parsing, protocol detection, proxy-aware IP resolution, and host/hostname parsing.
- **Response abstraction** — `ctx.response` wraps Node's `ServerResponse` with helpers for body type detection, redirects, ETags, caching headers, streaming, file attachments, and Content-Type negotiation.
- **AsyncLocalStorage support** — pass `asyncLocalStorage: true` (or an existing `AsyncLocalStorage` instance) to the constructor; `app.currentContext` returns the active context from anywhere in the call stack.
- **Web WHATWG body types** — response body can be a `Blob`, `ReadableStream`, or WHATWG `Response` object in addition to strings, Buffers, Node streams, and plain objects (auto-serialized to JSON).
- **ESM + CJS dual distribution** — ships `lib/` (CommonJS) and `dist/koa.mjs` (ESM wrapper), generated by `gen-esm-wrapper`.
- **Signed cookies** — built-in cookie support via the `cookies` package, with `app.keys` for KeyGrip-backed signing.
- **Proxy support** — configurable trust for `X-Forwarded-For`, `X-Forwarded-Proto`, and `X-Forwarded-Host` headers.
- **Custom middleware composition** — the `compose` function can be swapped at construction time (`new Koa({ compose: myCompose })`).

## Primary Use Cases and Target Audience

Koa targets Node.js backend developers who want a lightweight, low-level HTTP foundation. Common use cases include:

- **REST / JSON APIs** — set `ctx.body = object`, Koa serializes to JSON and sets headers automatically.
- **Streaming responses** — assign a Node.js Readable stream, `ReadableStream`, or `Blob` as `ctx.body`.
- **Server-Sent Events** — pipe a `PassThrough` stream as the body with `text/event-stream` content type.
- **HTTP/2 servers** — use `app.callback()` with Node's `http2.createSecureServer()`.
- **Middleware libraries** — the ecosystem (`koajs` org on GitHub) provides hundreds of composable middleware packages for routing, body parsing, static serving, CORS, authentication, etc.
- **Mounting into Express/Connect** — `app.callback()` returns a standard `(req, res)` handler.

## High-Level Architecture Overview

```
Application (extends EventEmitter)
  ├── middleware[]          — ordered array of async functions
  ├── compose()             — koa-compose: builds the middleware chain
  ├── callback()            — returns a (req, res) => void handler
  ├── createContext()       — instantiates Context per request
  ├── handleRequest()       — runs middleware chain, calls respond()
  ├── onerror()             — default app-level error handler
  └── ctxStorage            — AsyncLocalStorage (optional)

Context (prototype object, one instance per request)
  ├── request               — KoaRequest instance
  ├── response              — KoaResponse instance
  ├── app / req / res       — references to Application, IncomingMessage, ServerResponse
  ├── state                 — plain {} for per-request state sharing
  ├── cookies               — lazy Cookies instance
  ├── throw() / assert()    — http-errors / http-assert helpers
  └── delegates             — proxies methods/getters/setters from request & response

Request (prototype object)
  — Wraps IncomingMessage; provides: url, method, path, query, querystring,
    search, header/headers, host, hostname, URL (WHATWG), protocol, secure,
    ip, ips, subdomains, charset, length, fresh/stale, accepts/acceptsEncodings/
    acceptsCharsets/acceptsLanguages, is(), get(), type, idempotent, socket, origin, href

Response (prototype object)
  — Wraps ServerResponse; provides: status, message, body, length, header/headers,
    type, etag, lastModified, headerSent, writable, socket, redirect(), back(),
    attachment(), vary(), has(), set(), get(), append(), remove(), flushHeaders()
```

The `respond()` function in `application.js` (line 268) finalizes the HTTP response after all middleware settle, handling all body types and status-code edge cases.

## Related Projects and Dependencies

**Runtime dependencies:** `accepts`, `content-disposition`, `content-type`, `cookies`, `delegates`, `destroy`, `encodeurl`, `escape-html`, `fresh`, `http-assert`, `http-errors`, `koa-compose`, `mime-types`, `on-finished`, `parseurl`, `statuses`, `type-is`, `vary`.

**Key ecosystem packages:** `koa-router` / `@koa/router` (routing), `koa-body` / `koa-bodyparser` (body parsing), `koa-static` (static file serving), `koa-session` (session management), `koa-helmet` (security headers), `koa-cors` (@koa/cors), `koa-compose` (standalone middleware composition).
