OpenCode is an open source AI coding agent platform centered on a terminal-first developer experience, with companion web, desktop, SDK, and cloud surfaces layered around the same core runtime. The root README describes it simply as “The open source AI coding agent,” and the repository layout confirms that the project is broader than a single CLI binary: the monorepo includes the main `opencode` runtime, reusable core and LLM packages, a browser app, an Electron desktop app, a documentation site, a GitHub Action, cloud functions, enterprise and console applications, and generated SDKs. Its goal is to let users run AI-assisted development workflows locally or in connected environments while preserving a typed, inspectable, extensible architecture.

At the product level, OpenCode exposes several primary usage modes. The terminal CLI is the flagship interface, launched from the `packages/opencode` package and built around commands such as `run`, `serve`, `mcp`, `agent`, `providers`, `models`, `session`, `github`, `web`, and `db`. The README also highlights a built-in terminal UI and two built-in primary agents, `build` and `plan`, plus a `general` subagent for more complex delegated work. Beyond the terminal, the repo now ships a desktop app in `packages/desktop`, a web application in `packages/app`, a docs site in `packages/web`, and cloud-hosted supporting services defined under `infra/` and `packages/function`. There is also a GitHub Action under `github/` that lets repository users trigger OpenCode from issue comments and PR review threads.

The most distinctive capability in the codebase is the combination of typed session management, typed tool invocation, and provider-agnostic LLM orchestration. In `packages/opencode/src/session/`, OpenCode persists sessions, messages, tokens, summaries, share metadata, permissions, and revert information using Effect schemas and database-backed services. In `packages/opencode/src/tool/registry.ts`, it assembles the built-in tool surface—`shell`, `read`, `glob`, `grep`, `edit`, `write`, `task`, `task_status`, `webfetch`, `todo`, `search`, `repo_clone`, `repo_overview`, `skill`, `patch`, and optionally `lsp` and plan-mode tools—while merging plugin-provided tools discovered from workspace directories and installed plugins. In `packages/llm`, the project defines a schema-first abstraction over multiple provider protocols, exposing a normalized request, event, and tool language while keeping provider quirks inside adapters.

Architecturally, the repository is organized as a Bun/Turbo monorepo. `packages/opencode` is the executable heart of the system. Its `src/index.ts` bootstraps logging, one-time database migration, CLI argument parsing via `yargs`, and command registration. Under its `src/` tree, major subsystems include `agent/` for built-in and configured agent definitions, `session/` for chat lifecycle and prompt loops, `server/` for the HTTP API and event stream, `tool/` for local tool execution, `mcp/` for Model Context Protocol support, `skill/` for discovering prompt-time skills, `provider/` for model/provider selection, `project/` and `worktree/` for workspace state, and `storage/` for persistence. Supporting packages factor out shared responsibilities: `packages/core` holds portable schemas and provider/catalog primitives, `packages/llm` implements provider-neutral LLM requests and streams, `packages/sdk/js` generates client/server SDK surfaces, and UI packages wrap browser and desktop experiences.

The public API surface is also substantial. `packages/opencode/src/server/routes/instance/httpapi/api.ts` composes root and instance HTTP APIs out of groups such as `config`, `experimental`, `file`, `mcp`, `project`, `provider`, `pty`, `question`, `session`, `sync`, `tui`, `workspace`, and `v2`. The session group alone exposes endpoints for session listing, status, creation, deletion, forking, diffing, prompting, shell execution, revert, permission responses, and message access. The root API adds global health, config, event, dispose, and upgrade endpoints. A newer `v2` namespace groups experimental `session`, `message`, `model`, and `provider` APIs, and `packages/sdk/js/script/build.ts` generates SDK clients directly from the OpenAPI description emitted by the running server.

OpenCode targets several audiences: individual developers using a local coding agent, teams building automation around sessions and tools, platform engineers embedding the HTTP or SDK layer, and downstream projects integrating the GitHub Action, plugins, or enterprise/web console surfaces. The repo depends heavily on Bun, Effect, Zod, Drizzle ORM, Solid, Vite, SST, Hono, Cloudflare services, and the AI SDK/provider ecosystem. Together these pieces make OpenCode both an end-user product and an extensible platform for AI-assisted software development workflows.
