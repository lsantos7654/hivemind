## Summary

HTTPX is a next-generation HTTP client for Python 3, designed as the spiritual successor to the popular `requests` library, with a broadly requests-compatible API. Its primary purpose is to provide a modern, fully-featured HTTP client that supports both synchronous and asynchronous programming models. Created by Tom Christie and the Encode team, httpx delivers HTTP/1.1 and optional HTTP/2 support, an integrated command-line client, and the unique ability to make requests directly to WSGI and ASGI applications — making it useful not only as an HTTP client but also as a testing and development tool for Python web applications.

The library's key features include: a broadly requests-compatible API surface, an integrated command-line client (accessible via `httpx` on the command line), HTTP/1.1 and HTTP/2 support, both synchronous (`httpx.Client`) and asynchronous (`httpx.AsyncClient`) interfaces, direct-to-WSGI and direct-to-ASGI transports for testing, strict timeout enforcement across all operations, full type annotation coverage, and 100% test coverage. It also carries forward all the standard features expected from a modern HTTP client: international domain support, keep-alive and connection pooling, session-based cookie persistence, browser-style SSL verification, Basic and Digest authentication, automatic decompression, streaming downloads, multipart file uploads, and proxy support.

The primary use cases span web API consumption, web scraping, integration testing of Python web applications (via WSGI/ASGI transports), and any general-purpose HTTP client needs in the Python ecosystem. The target audience includes web developers, backend engineers, API integrators, and anyone building Python applications that need to communicate over HTTP.

At a high level, httpx is architected into distinct layers: a top-level API layer (`_api.py`) providing convenience functions like `httpx.get()` and `httpx.post()`, a client orchestration layer (`_client.py`) with `Client` and `AsyncClient` that manages sessions, redirects, authentication, and event hooks, a models layer (`_models.py`) defining `Request`, `Response`, `Headers`, and `Cookies` data classes, and a transport abstraction layer (`_transports/`) that defines a pluggable interface (`BaseTransport` / `AsyncBaseTransport`) backed by implementations including the default `HTTPTransport` (wrapping the `httpcore` library), `ASGITransport`, `WSGITransport`, and `MockTransport`.

HTTPX depends on `httpcore` (its low-level HTTP transport sibling from the same Encode team) for HTTP/1.1 and HTTP/2 networking, `anyio` for async backends (asyncio, trio), `certifi` for SSL certificate verification, and `idna` for international domain name handling. Optional extras include `h2` for HTTP/2, `brotli`/`brotlicffi` and `zstandard` for compression codecs, `socksio` for SOCKS proxy support, and `click`/`rich`/`pygments` for the CLI client.
