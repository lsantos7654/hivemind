# openai-node — Repository Summary

## Repository Purpose and Goals

`openai-node` (npm package: `openai`, v6.32.0) is the **official TypeScript/JavaScript client library for the OpenAI REST API**. It is generated from OpenAI's OpenAPI specification using the [Stainless](https://stainlessapi.com/) SDK generator. Its primary goals are to:

- Provide idiomatic, type-safe access to all OpenAI API endpoints from Node.js, Deno, Bun, Cloudflare Workers, and web browsers.
- Abstract away HTTP plumbing (retries, timeouts, pagination, streaming, file uploads) so developers can focus on product logic.
- Support both the modern **Responses API** and the legacy **Chat Completions API**, plus beta features (Assistants, Realtime WebSocket, Realtime Transcription).
- Offer first-class TypeScript types for every request parameter and response shape.

## Key Features and Capabilities

- **Responses API** (`client.responses.create`): The current primary API for text and multimodal generation, supporting structured outputs, function calling, vision, and built-in tools.
- **Chat Completions API** (`client.chat.completions.create`): Mature endpoint supporting streaming, tool calls, function running, and structured outputs via Zod or JSON Schema.
- **Streaming via SSE / Server-Sent Events**: Both Responses and Chat Completions support `stream: true`, returning rich `AsyncIterable` streams with typed events.
- **Realtime API** (`OpenAIRealtimeWebSocket`, `OpenAIRealtimeWS`): Low-latency bidirectional WebSocket for real-time voice/text conversations.
- **Auto-pagination**: All list endpoints implement `AsyncIterable<Item>`, automatically fetching subsequent pages.
- **File uploads**: Accepts `File`, `fs.ReadStream`, `fetch Response`, or the `toFile()` helper for multipart uploads.
- **Structured outputs / Zod integration**: `zodResponseFormat()` and `zodTextFormat()` in `src/helpers/zod.ts` convert Zod schemas (v3 or v4) to OpenAI JSON Schema with strict-mode compatibility.
- **Tool calling helpers**: `ChatCompletionRunner`, `ChatCompletionStreamingRunner`, and `RunnableFunction` abstractions simplify the tool-call loop.
- **Webhook verification**: `client.webhooks.unwrap()` / `client.webhooks.verifySignature()` validate HMAC-SHA256 webhook signatures.
- **Azure OpenAI support**: The `AzureOpenAI` class extends `OpenAI` with Azure-specific authentication (API key or Microsoft Entra token provider).
- **Configurable fetch**: Custom `fetch` implementations, proxy configuration, and `fetchOptions` pass-through.
- **Logging**: Configurable log levels (`debug`, `info`, `warn`, `error`, `off`) with custom logger support (pino, winston, bunyan, etc.).
- **Automatic retries**: Exponential backoff on 408, 409, 429, 5xx errors; configurable `maxRetries`.
- **Request IDs**: All responses expose `_request_id` from the `x-request-id` header for debugging.

## Primary Use Cases and Target Audience

- **Application developers** building AI-powered features (chat, code generation, search, summarization) on any JS/TS runtime.
- **Backend engineers** integrating OpenAI APIs into Node.js services, Cloudflare Workers, or Vercel Edge functions.
- **ML engineers** using fine-tuning, batch processing, embeddings, or evals pipelines.
- **Real-time voice application developers** using the Realtime WebSocket API.
- **Enterprise teams** using Azure OpenAI Service.

## High-Level Architecture Overview

The library follows a resource-per-endpoint pattern generated by Stainless:

```
OpenAI (client)
├── responses          → Responses API (text/image/tool generation)
├── chat.completions   → Chat Completions API
├── audio              → TTS, transcription, translation
├── embeddings         → Vector embeddings
├── images             → Image generation and editing
├── files              → File management
├── fineTuning         → Fine-tuning jobs and checkpoints
├── vectorStores       → Vector store CRUD
├── batches            → Batch processing
├── moderations        → Content moderation
├── models             → Model listing/retrieval
├── evals              → Model evaluations
├── containers         → Container management
├── conversations      → Conversation threads
├── realtime           → Realtime session/call management
├── graders            → Grader models
├── skills             → Skills management
├── uploads            → Multipart upload sessions
├── webhooks           → Webhook signature verification
└── beta
    ├── assistants     → Assistants API
    ├── threads        → Thread + Message + Run management
    ├── realtime       → Beta Realtime sessions
    └── chatkit        → Beta chat kit sessions
```

**Internal layers:**
- `src/client.ts` — Main `OpenAI` class, HTTP engine, retry/timeout logic
- `src/core/` — `APIPromise`, `AbstractPage`, `Stream`, error types, upload utilities
- `src/internal/` — Platform detection, headers, query serialization, shims, logging
- `src/lib/` — Higher-level helpers: stream runners, Zod integration, event emitters
- `src/realtime/` — WebSocket and `ws` transport for Realtime API
- `src/_vendor/` — Vendored `partial-json-parser` and `zod-to-json-schema`

## Related Projects and Dependencies

- **Runtime dependencies**: None (zero production dependencies)
- **Peer dependencies**: `ws` ^8.18.0 (optional, for Node.js Realtime WebSocket), `zod` ^3.25 || ^4.0 (optional, for structured outputs)
- **Dev dependencies**: TypeScript 5.8.3, Jest, `@swc/jest`, ESLint, Prettier, `tsc-multi` (dual CJS/ESM build)
- **Generated from**: [openai/openai-openapi](https://github.com/openai/openai-openapi) via Stainless
- **Published to**: npm as `openai` and JSR as `@openai/openai`
- **Azure identity integration**: Works with `@azure/identity` for Entra token-based auth
