# Toolong — Build System

## Build System Type

Toolong uses **[Poetry](https://python-poetry.org/)** as its build and dependency management system. The build backend is `poetry.core.masonry.api` from the `poetry-core` package.

Configuration is entirely in `pyproject.toml` (PEP 517/518 compliant). There is no `setup.py`, `setup.cfg`, or `Makefile`.

## Configuration Files

### `pyproject.toml`
The single source of truth for the project:
```toml
[tool.poetry]
name = "toolong"
version = "1.5.0"
description = "A terminal log file viewer / tailer / analyzer"
authors = ["Will McGugan <will@textualize.io>"]
license = "MIT"
readme = "README.md"
homepage = "https://github.com/textualize/toolong"
repository = "https://github.com/textualize/toolong"
documentation = "https://github.com/textualize/toolong"

[tool.poetry.dependencies]
python = "^3.8"
click = "^8.1.7"
textual = "^0.58.0"
typing-extensions = "^4.9.0"

[tool.poetry.group.dev.dependencies]
textual-dev = "^1.4.0"

[tool.poetry.scripts]
tl = "toolong.cli:run"

[build-system]
requires = ["poetry-core"]
build-backend = "poetry.core.masonry.api"
```

### `poetry.lock`
Fully pinned dependency lock file generated by Poetry. Ensures reproducible installs across environments. Not meant to be edited manually.

## Package Structure

The project uses a **`src` layout**. Poetry automatically discovers the `toolong` package inside `src/`:
```
src/
└── toolong/          # Importable package
    ├── __init__.py
    └── ... (all modules)
```

The console script entry point is registered as:
```
tl = "toolong.cli:run"
```
This makes the `tl` command available on the PATH after installation.

## How to Build, Test, and Deploy

### Installation (End Users)

Recommended via **pipx** (isolated environment):
```bash
pipx install toolong
```

Or via pip (ideally in a virtual environment):
```bash
pip install toolong
```

### Development Setup

```bash
# Install Poetry if not available
pip install poetry

# Clone the repository
git clone https://github.com/Textualize/toolong
cd toolong

# Install all dependencies (including dev group)
poetry install

# Activate the virtual environment
poetry shell

# Run the CLI directly
tl --help
```

### Running the Application

```bash
# View one or more files
tl mylogfile.log
tl access.log error.log

# Merge multiple files by timestamp
tl access.log.1 access.log.2 --merge

# Save merged output
tl access.log.* --merge --output-merge merged.log

# Pipe data
echo "hello world" | tl
tree / | tl
```

Also runnable as a Python module:
```bash
python -m toolong myfile.log
```

### Building a Distribution

```bash
# Build both sdist and wheel
poetry build
# Output: dist/toolong-1.5.0.tar.gz and dist/toolong-1.5.0-py3-none-any.whl
```

### Publishing to PyPI

```bash
# Configure PyPI token first
poetry config pypi-token.pypi <token>

# Publish
poetry publish
```

### Development Tools

With `textual-dev` installed, you can use Textual's live development features:

```bash
# Run with Textual devtools (shows logs in a separate panel)
textual run --dev toolong/ui.py

# Open Textual CSS inspector
# (press Ctrl+\ in the app when running with textual-dev)
```

### Testing

There is no test suite in the repository at commit `5aa22ee`. The project does not include `pytest` or any other test framework in its dependencies. Testing appears to be done manually or through integration testing by running the application against real log files.

### Upgrading Dependencies

```bash
# Update all packages to latest compatible versions
poetry update

# Update a specific package
poetry update textual

# Show outdated dependencies
poetry show --outdated
```

## Compatibility

- **Python**: 3.8 and above (^3.8)
- **Operating Systems**: Linux, macOS, Windows (all supported)
  - macOS uses `SelectorWatcher` (kqueue via `selectors.DefaultSelector`)
  - Linux/Windows use `PollWatcher`
  - Windows uses lseek+read instead of `os.pread` for thread-safe file reads
- The `tl` piping feature uses `/dev/tty` which is POSIX-specific; Windows piping may have limitations.

## Source Layout Rationale

The `src/` layout prevents the package from being accidentally importable from the repository root during development without installation. This is a best practice that ensures the installed package is always used during testing and development, preventing subtle import path issues.
